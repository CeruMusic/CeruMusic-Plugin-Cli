# 本地候选的验证范围

本文对应尚未发布的桌面 2.5.0 与插件工具链 3.0.0。冻结的 v2 0.3.16 不增加新接口。安装、签名与发布仍是独立步骤，不能把本地构建通过当成已经发布。

桌面候选 `app.asar` 的 SHA-256 为 `4D494310D4B4B0BC781382FDEE37759E517BFA1F4509B942C308F5C8B8EA7965`。该包的 14 项实际 Electron 检查通过，覆盖共享组件、旧新插件并存、舞台与桌面歌词、真实 CLI 页面与皮肤热更新、面板动画、区域异常及慢帧回退、音源选择与禁用原因提示，以及表单、二维码、OAuth、浏览器登录。账号服务响应使用测试夹具，不是真实平台账号。

默认界面和插件皮肤各连续播放一分钟，平均主帧工作耗时分别为 1.919/0.805ms，绝对差 1.114ms，未观察到逐帧 worker 消息。该数字是本机主帧工作耗时，不是显示器帧率保证。另一项无 hook 的连续切歌对照虽然当前版本更快约 36.905ms，但没有通过计划要求的绝对差 ≤5ms；不能把两个指标混为一项。

作者工具的五个包和全部模板已经过 26 个 JS/TS 独立安装组合的检查，包括类型检查、构建、产物校验、移动目录、Vue 子组件、皮肤编译错误恢复与动画钩子。使用已有 npm 缓存；空缓存机器仍需要下载第三方依赖。只有文档变化的开发包可通过五个归档及创建脚本的逐字节比对沿用这些结果。

服务专项另覆盖真实 worker HTTP、端口归属、取消与撤权、独立 utilityProcess、Express/Koa、Node-API 和单独同意流程，以及三种加密音源模板、内置解密、WASM 变换、下载和缓存。完全信任入口没有文件隔离；实际能力与同意说明见 [服务与音频流](SERVER-AND-STREAMS.md)。旧方案与失败证据见 [历史验证记录](SERVER-AND-STREAMS-HISTORY.md)。

以下仍不能标为完成：

- 在一次性 Windows 虚拟机中执行两次真实旧版覆盖升级，核对原插件、配置、权限、存储与子插件。
- 用真实 DLNA 接收器播放、跳播加密音频，并从第二台 LAN 设备检查监听权限与撤权后的连接关闭。
- 用真实平台账号完成扫码或网页登录、账号切换、续期和受授权的同步。
- 无 hook 连续切歌的绝对差 ≤5ms 门槛。

完整测试日志和阶段记录保存在开发仓库的 `docs/v3-local-qa.md` 与桌面仓库的 `docs/plugin-upgrade-local-qa.md`，不随本文宣称人工项目已经通过。
